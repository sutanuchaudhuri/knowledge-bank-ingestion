Competition Math Intelligence Platform

From a crawled PDF to evidence-based help
— one learning step at a time.

MathBank turns raw competition-math papers (AMC/AIME/AIME-style PDFs and AoPS wiki pages) into a queryable corpus, a knowledge graph, a hybrid search engine, and an agentic tutor — with every ingestion stage tracked in Postgres and every graph fact traceable back to its source. This presentation distinguishes historical corpus snapshots, the P0 pedagogical implementation scope, and planned learner personalization. Start with the learning loop.

In plain terms: this system takes thousands of real competition math problems, figures out what each one is really testing (which topic, which technique), and uses that understanding to power a tutoring agent that can answer a student's question with real, cited problems — and eventually track what each student has and hasn't mastered, so practice becomes targeted instead of random.

01The layers, at a glance

Every later page drills into one of these. The boundary rule that holds the whole system together: the agent never touches a database directly — it only calls mathbank-rest, which is the single boundary onto Postgres and Neo4j. The live classroom (mathbank-live) is deployed separately and also reaches the data only through mathbank-rest. The ElevenLabs key stays in Next.js server routes.

02Principles that show up everywhere

Idempotency

Nothing duplicates on re-run

Every loader upserts on a natural key (canonical_code, slug, external_code). Re-running the whole pipeline from a clean checkout never creates a duplicate row — verified via duplicate-key audits in the classification export step.

Traceability

Every stage is logged in a table

pipeline.run, pipeline.graph_projection, pipeline.pdf_source, and a local ingestion_runs SQLite table mean you can answer "did this actually finish, and when" months later, not just by scrollback through a terminal.

Postgres is the system of record

Neo4j is a derived view

The graph is never hand-edited — it's re-projected from Postgres by Cypher MERGE, so it's always safe to wipe and rebuild it.

REST is the only door

The agent cannot query the DB directly

Every tool the tutoring agent can call is a narrow, versioned REST endpoint — this is what makes prompt-injection containment and query governance possible.
