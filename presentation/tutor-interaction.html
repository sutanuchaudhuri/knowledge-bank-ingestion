What actually happens during a chat turn

The UI on the left is a mock — the real mathbank-web chat interface may look different and will keep changing. What this page holds fixed is the sequence of real systems that fire for every message: which layer is active, what REST call is made, what SQL or Cypher actually runs, and how the vector DB gets involved. These three conversations are historical replay snapshots, not the P0 anonymous /learn flow. Their status badges describe the earlier implementation record, not current deployment verification.

P0The new teaching interaction

Choose the obstacle (concept, strategy, execution, calculation, connection), request an attempt, and offer one hint at a time (1–3). When a detour helps, retrieve reviewed prerequisites or easier same-skill evidence; otherwise disclose the gap. An on-demand generated micro-lesson or hint is PENDING, does not receive official answer / solution context, and ends with a return_prompt to the original problem. This is not a persisted P1 hint library or a P2 learner model.

BWhy show it this way

A screenshot of the chat UI tells you nothing about why an answer took 2 seconds, or why a competition filter does or doesn't return results, or what "mastery" actually means under the hood. Every code block on this page is the real call shape or real (abbreviated) SQL/Cypher from this codebase — see Use Cases for the full, unabridged versions and Ingestion & Inference for the sequence-diagram summary of Turn 1. The honesty convention holds here too: Turn 2's graph-based prerequisite step is marked planned, not live — the mastery math is real, the graph traversal on top of it isn't wired yet. Turn 3 was originally a design sketch; as of Round 11 it's mostly built: a real POST /v1/tutor/decompose (OpenAI JSON-mode call that breaks a fetched problem statement into 2-5 subproblems without revealing the answer) and POST /v1/tutor/check-subproblem (grades a free-form answer to one subproblem), both wrapped 1:1 as agent tools (decompose_problem/check_subproblem_answer) and verified live against the real corpus and OpenAI. learner.attempt.hint_count now actually discounts mastery scoring too (mastery.hint_penalty(), MST-09) — closing the gap this turn used to call out. What's still marked mixed, not fully live: logging a hint against one specific subproblem (no core.subproblem table exists, so hints still log against the parent problem), and whether the agent reliably chains decompose → grade → detect-weakness → remediate end-to-end from its own reasoning versus needing more explicit step-by-step instructions. See requirements/10_AGENTIC_TUTOR_AND_STUDENT_MASTERY_REQUIREMENTS.md (AGT-11, MST-09) and mathematics_tutor_db_plan/00_implementation_progress.md (Round 11) for the full implementation record.
