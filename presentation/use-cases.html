AUse case 1 — Hybrid search ("find me combinatorics problems from AIME")

Who uses this & why technical + business

For a student or teacher: type a topic in plain English, get back real problems — no need to know the exact taxonomy name or browse by competition manually.

Implementation: Reciprocal Rank Fusion (RRF) over two candidate lists — pgvector cosine-similarity ANN search and Postgres full-text search — combined with a pre-filter CTE so competition/year filters narrow the candidate pool before ranking, not after.

POST /v1/search/problems
{
  "query": "combinatorics counting problems",
  "filters": {"competition": "AIME"},
  "retrieval": {"semantic": true, "lexical": true},
  "order_by": "year_desc",
  "limit": 10
}
-- the pre-filter CTE that fixed a real empty-results bug
WITH eligible_problem AS (
    SELECT p.problem_id FROM core.problem p
    JOIN core.paper pa ON pa.paper_id = p.paper_id
    JOIN core.competition_edition ed ON ed.edition_id = pa.edition_id
    JOIN core.competition comp ON comp.competition_id = ed.competition_id
    WHERE comp.external_code = 'AIME'
),
semantic AS (
    SELECT e.chunk_id, row_number() OVER (ORDER BY e.embedding <=> :query_vector) AS rnk
    FROM search.embedding e JOIN search.chunk c ON c.chunk_id = e.chunk_id
    JOIN eligible_problem ep ON ep.problem_id = c.problem_id
    ORDER BY e.embedding <=> :query_vector LIMIT 100
)
-- ... lexical CTE mirrors this, then RRF: 1/(60+rank_semantic) + 1/(60+rank_lexical)

BUse case 2 — Agent tutoring ("explain why the answer to this is 17")

Who uses this & why technical + business

For a student: a chat interface that answers with real, cited problems and solutions — never a hallucinated problem, because the agent is structurally forbidden from answering without evidence from a tool call.

Implementation: Google ADK LlmAgent + LiteLlm connector to OpenAI (not Gemini). The agent's only capability is calling narrow, versioned REST tools — it cannot query Postgres/Neo4j directly, which is also the primary prompt-injection containment boundary.

Toolsearch_problems(query, filters, order_by) → POST /v1/search/problems
Toolget_problem(canonical_code) → GET /v1/problems/by-code/{code}
Tool (planned)get_student_mastery_summary(student_id) → GET /v1/learner/mastery
Grounding ruleFinal answer may only cite problems that appeared in a tool response this turn

CUse case 3 — Admin adds a new competition

Who uses this & why technical + business

For a content operator: paste a competition's page URLs into a form — the system tracks every paper's progress (downloaded? parsed? loaded?) without needing a developer to run scripts by hand.

Implementation: POST /v1/admin/papers writes straight to pipeline.pdf_source with status=PENDING — the existing reconcile/ingest commands are format-agnostic (they only check for questions/Qnn/problem.md on disk), so a brand-new stdlib-only HTML fetch path needed zero changes to either.

curl -X POST /v1/admin/competitions -H "X-Admin-Api-Key: $KEY" \
  -d '{"external_code":"NEW_COMP","name":"New Competition"}'

curl -X POST /v1/admin/papers -H "X-Admin-Api-Key: $KEY" \
  -d '{"paper_external_code":"PAPER_NEW_COMP_2027_TEAM",
       "competition_external_code":"NEW_COMP","year":2027,
       "problem_url":"https://...","source_kind":"PDF"}'
# → pipeline.pdf_source row created instantly: download_status=PENDING

Then: make pdf-fetch (PDF via Docling, HTML via stdlib) → make pdf-reconcile → make pdf-ingest — each stage updates its own status column, visible live in the admin dashboard.

DUse case 4 — Student mastery tracking backend live, graph pending

Who uses this & why technical + business

For a student: instead of random practice, the system remembers what you've gotten right and wrong recently, and weights recommendations toward what you're actually struggling with — recent performance counts more than something you got right six months ago.

Implementation: time-decayed, difficulty-weighted accuracy, recomputed inline after every attempt. Fully implemented in Postgres; the Neo4j MASTERED/STRUGGLES_WITH projection is designed (threshold-based, score ≥0.8 / <0.4) but not yet wired — the mastery math works today, the graph-based recommendation doesn't yet.

POST /v1/learner/attempts  (Authorization: Bearer <jwt>)
{"problem_code": "AIME_1983_Q01", "is_correct": true, "time_spent_seconds": 120}
→ recomputes learner.concept_mastery / technique_mastery inline, returns updated scores

GET /v1/learner/mastery → {"concepts": [...], "techniques": [...]}

$$ \text{mastery}(s,c) = \dfrac{\sum_a \text{correct}(a)\cdot e^{-\text{days}/45}\cdot(1+0.5\cdot\text{difficulty}(a))}{\sum_a e^{-\text{days}/45}\cdot(1+0.5\cdot\text{difficulty}(a))} $$

EUse case 5 — Student solves a textbook problem step by step implemented · AI

Who uses this & why technical + business

For a student: the problem is split into the real reasoning steps from the textbook. You answer one step at a time. A hint ladder goes from a gentle nudge to a near-explicit step, and the tutor always knows which step you are on and how much help you have used.

Implementation: /learn/solve/[code] renders the problem with its STUDENT_PROBLEM diagrams. SOLUTION_HIDDEN diagrams are never sent. Each response is graded as CORRECT / PARTIALLY_CORRECT / INCORRECT / OFF_TOPIC and stored in learner.attempt_step_state and the append-only learner.event, with an idempotency key. Hints: L1 directional → L2 concept reminder → L3 strategic → L4 near-explicit (cached in pedagogy.step_hint) → L5 full reveal (the canonical step text, which caps credit).

POST /v1/students/{student_id}/problems/{problem_ref}/attempts   → solve_attempt (IN_PROGRESS)
GET  /v1/attempts/{attempt_id}/runtime                            → current step, mode, help used
POST /v1/attempts/{attempt_id}/steps/{step_id}/responses          → verdict + feedback
POST /v1/attempts/{attempt_id}/steps/{step_id}/hint   {"level": 2} → next hint (Idempotency-Key header)
POST /v1/attempts/{attempt_id}/submit

FUse case 6 — Knowledge-gap diagnosis and recovery detour implemented · AI

Who uses this & why technical + business

For a student: when you are stuck, the tutor works out which earlier idea is probably missing, takes you through a short practice path on that idea, and then brings you back to the exact step you were on.

Implementation: diagnose ranks hypotheses from the step's skill, its prerequisite steps in the DAG, and the taxonomy. They are shown as likely / possible / worth checking, with optional AI re-ranking. A recovery_plan stores the origin_step_id and orders its items through the stages Worked example → Recognise the idea → Use it once → Use it in context → Try it somewhere new → Back to your problem. Items come from approved learning items (MCQ, subproblem, theory) rendered with KaTeX.

POST /v1/attempts/{attempt_id}/steps/{step_id}/diagnose          → gap_diagnosis + ranked knowledge_gap rows
POST /v1/attempts/{attempt_id}/recovery-plans                      → recovery_plan (mode RECOVERY)
GET  /v1/recovery-plans/{plan_id}/next                             → next item by stage
POST /v1/recovery-plans/{plan_id}/items/{item_id}/responses
POST /v1/recovery-plans/{plan_id}/resume                           → back to origin step (mode SOLVING)

GUse case 7 — The AI tutor drives the step runtime implemented · AI

Who uses this & why technical + business

For a student: you can ask the chat tutor for help, and it uses the same steps, hints and recovery plans as the workspace, so the two never contradict each other.

Implementation: the ADK agent has 24 REST-backed tools, including start_step_attempt, get_attempt_runtime, submit_step_response, request_step_hint, diagnose_step_gap, start_recovery_plan, get_next_recovery_item, answer_recovery_item, resume_original_step, propose_widget and format_math. The student token is kept in temp:student_token and removed before the session is saved. The agent coordinates calls; deterministic services own the state.

IUse case 9 — Admin imports a textbook and reviews its step DAG implemented

Who uses this & why technical + business

For a content operator: import a textbook package (for example Prasolov chapters 1–30), see exactly what was created, updated or rejected, resolve conflicts, and correct a solution's step graph before students see it.

Implementation: make textbook-import-remote registers an ingest.content_package and stages, validates, reconciles and upserts it idempotently. /admin/imports shows packages, issues, reconciliation counts and conflicts (KEEP_EXISTING / ACCEPT_INCOMING / MERGE_MANUALLY). It also supports step and dependency edits, DAG review, and learning-item review. Every decision is written to ingest.admin_review_action. Projection requests queue the graph and embedding refresh. /admin/textbooks browses problems, solutions, steps, taxonomy and diagrams.

GET  /v1/admin/imports/packages · /reconciliation · /packages/{id}/conflicts
POST /v1/admin/imports/conflicts/{conflict_id}/decision
GET  /v1/admin/imports/problems/{code}/dag   → POST …/dag/review
PATCH /v1/admin/imports/steps/{step_id}  ·  PUT /v1/admin/imports/dependencies
POST /v1/admin/imports/learning-items/{learning_item_id}/review
GET,POST /v1/admin/imports/projection-requests

Other admin pages: /admin/knowledge-gaps (gaps and recovery plans across students), /admin/pedagogy (metadata approval), /admin/widgets (widget gallery and specs). See 24_ADMIN_TEXTBOOK_CORPUS_DASHBOARD.

JUse case 10 — Instructor runs a live classroom implemented

Who uses this & why technical + business

For an instructor: plan a lesson with the AI, publish it, and run it live. Students join with a code, answer polls and MCQs, and use interactive widgets, while the AI tutor and the clock suggest when to move on. You can take over a whole session, one student or one group.

Implementation: mathbank-live (Next.js + Socket.IO, :5174) is deployed separately and proxies to /v1/live, /v1/instructor/live and /v1/authoring. Pages: /i/[sid] instructor console and /s/[sid] student classroom. Socket events live:join/live:op/live:event use session, student, group and instructor rooms. An event pump reads live.session_event with ?after= every 700 ms. ask_tutor is rate-limited to 6 per minute. See 27 and 28.

POST /v1/authoring/presentation-plans → …/validate → …/approve → …/publish
POST /v1/live/sessions  → join_code;  POST /v1/live/sessions/join
POST /v1/live/sessions/{sid}/activities → …/{aid}/close → …/{aid}/reveal → …/aggregate
GET  /v1/instructor/live/{sid}/recommendations → POST …/{rid}  (accept / dismiss)

KUse case 11 — Faster input: LaTeX composer and ElevenLabs voice implemented

Who uses this & why technical + business

For a student: type maths quickly with a LaTeX composer that has a live preview and shortcut buttons, ask the AI to tidy up your notation, or just speak your answer and hear the tutor reply.

Implementation: the shared mathbank-widgets package (MathComposer, VoiceControls, WidgetHost) is used by both web apps. The /api/format-math route does agent-assisted formatting. /api/voice/stt, /api/voice/tts and /api/voice/health are Next.js server routes that hold ELEVEN_API_KEY, so the key never reaches the browser.
