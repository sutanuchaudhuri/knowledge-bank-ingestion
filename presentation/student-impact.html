Why this matters for a student

This page is intentionally written for a non-technical audience — a teacher, a parent, a program director. Every claim here links back to something real and working, not a roadmap promise.

AThe problem with generic practice sets

"More problems" isn't the same as "the right problems"

A student who's shaky on casework (combinatorics) doesn't improve by grinding geometry problems, no matter how many of them they do. Most practice platforms can't tell the difference because they don't actually know what a problem is testing.

Competitions don't come with their own index

AMC, AIME, SMT, PUMaC, CHMMC — each publishes problems and official solutions, but none of them tag "this problem is really about the Pigeonhole Principle." Building that index by hand for thousands of problems isn't realistic. Building it with AI, and checking the AI's work, is what this system does.

BHow MathBank is different

Today

Ask in plain English

"Show me recent AIME problems about combinatorics" returns real, cited problems — not a keyword match, a genuine understanding of what each problem tests.

Today

Every answer is grounded

The tutoring agent can only cite problems it actually retrieved this turn — it is structurally unable to invent a problem that doesn't exist in the corpus.

Coming next

Personalized to what you struggle with

The mastery-tracking backend already computes a decaying, difficulty-aware score per student per concept — the next step is having the tutor actually use it to steer recommendations.

CAn honest look at where quality is still improving

This platform is built to show its work rather than hide weak spots behind a demo. Two real examples, found by the system's own quality checks:

Classification coverage varies by competition

AMC/AIME are ~99% tagged with a concept; smaller archives like CHMMC/PUMaC/SMT started at 0-5% and are being brought up to parity with dedicated classification batches (in progress as of this page). Search quality for those competitions improves directly as coverage grows — it's measurable, not vague.

Search quality is measured, not assumed

Precision/Recall/MRR are computed against a real golden-query set after every change, and trended over time — so a change that looks fine in a demo but quietly regresses search quality gets caught.

The honest status: A and B are live today. C/D/E/F/G are designed (see the mastery use case and the dashed edges on the graph model page) and are the next concrete build target, not a vague future promise — the prerequisite-gap Cypher query is already written and tested conceptually against the current HAS_SUBCONCEPT hierarchy.
